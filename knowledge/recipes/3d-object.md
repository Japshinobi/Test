# Рецепт: 3D-объект (постройка, предмет обстановки)

## Когда использовать

- «Сделай камни (стог, пугало, забор, теплицу…) объёмными».
- Новая постройка или предмет, который по правилу из [[pixel-art]] должен быть в 3D: у него есть перед и зад или он шире клетки.
- Правка существующей 3D-модели (дом, прилавки, шатёр, фонтан, колодец, ящики, табличка, указатель, шлагбаумы).

## Что уже есть в игре

Все 3D-модели строятся кодом в `godot/scripts/world.gd`, вызываются из `build(...)` по полю `"model"` каталога:

| `model` | Функция | Объекты |
|---|---|---|
| `house` | `_house` | дом |
| `stall`, `tent` | `_shop` → `_stall`, `_tent` | прилавки (`stall`, `stallside`, `stallback`), шатёр |
| `fountain` | `_fountain` | фонтан |
| `well` | `_well` | колодец |
| `bin`, `mailbox`, `sign`, `signpost`, `barrier` | `_prop` | ящик для продажи, почтовый ящик, табличка, указатель, шлагбаумы |

- **Помощники для форм:**
  - `_box` — коробка;
  - `quad`, `tri` — четырёхугольник и треугольник;
  - `_ring_wall`, `_ring_top`, `_disc` — круглые стенки, верх кольца, круг;
  - `_surface()` → `_add_mesh(родитель, st, материал)`.
- **Текстуры** рисуются кодом там же, 16 пикселей на клетку:
  - дерево — `_planks`, `_counter`, `_post`, `_sign_board`, `_well_roof`;
  - камень — `_stone`, `_stone_light`;
  - снег — `_snow_roof`;
  - ткани — `_stripes`, `_valance`;
  - разное — `_shutters`, `_plaque`, `_mailbox`, `_barrier_bar`;
  - одноцветная — `_img(w, h, цвет)`.
- **Палитра:** любая текстура до 64×64, прошедшая через `_material`, притягивается к палитре «3d» (`palette.gd` → `quantize`). Рисовать текстуры можно примерными цветами, но лучше брать их прямо из палитры: `Palette.col("3d", "wood", 1)`.
- **Материалы** — `_mat(ключ, картинка)`: один материал на ключ за постройку локации. Таблица `_mats` очищается в `build`.
- **Вода в чаше** — `_water_disc` (кадры воды и льда из атласа, анимирует `tick` через `_small_waters`). **Струи** — `_jets` (частицы).
- **Поворот** — поле `"facing"` в каталоге (`south`, `north`, `east`, `west`). Сейчас его понимает только `_shop`.
- **Торговец за прилавком** — спрайт `trader_<who>` (`_trader`), открыто или закрыто — `_show_shop` из `set_market_open`.

## Какие файлы затрагиваются

- `godot/scripts/world.gd` — новая функция модели и ветка в `build`.
- `godot/data/objects.json` — `"model": "<имя>"` у объекта (и `"facing"`, если у модели есть перед). Поле `"sprite"` оставить: по нему объект виден в редакторе карт.
- `godot/scripts/farm_net.gd` → `act` — только если у объекта новое поведение при тапе. Поведение привязано к `id` объекта, а не к модели, поэтому переход на 3D его не меняет.
- `knowledge/style/pixel-art.md` (список «Сделано в 3D»), `knowledge/decisions/data.md` (значения `model`), этот рецепт (таблица выше).

## Шаги по порядку

1. **Посмотреть, как объект нарисован сейчас:** функция `draw…` в `game/sprites.js` и спрайт в арт-библии `game/catalog.html`. Взять оттуда форму и **цвета** (палитра — [[pixel-art]]).
2. **Узнать размер и место:** `"size"` в каталоге, позиции на картах (`godot/maps/*.json`), текст и поведение (`act`).
3. **Написать функцию модели** в `world.gd`:
   - корень — `Node3D` в `content`;
   - начало координат — середина клеток объекта (как в `_prop`) или левый верхний угол (как в `_house`, `_shop`);
   - формы — `_box` и кольца, текстуры по 16 пикселей на клетку;
   - **снег:** при `snow` на верхние поверхности — `_snow_roof` (крыша, крышка, верх бортика);
   - **зима без снега:** вода — лёд (`winter`);
   - тени отбрасываются сами; если что-то не должно давать тень — `cast_shadow = SHADOW_CASTING_SETTING_OFF`.
4. **Ветка в `build`:** `if d.get("model", "") == "<имя>": …; continue`.
5. **Каталог:** `"model"` (и `"facing"`). Проверить, что JSON читается.
6. **Если внутри что-то должно быть видно** (торговец, мебель) — крыша высоко или прозрачная. Правило в [[lessons]]: край крыши выше h + 1,2·Δz.
7. **Обновить базу знаний** (файлы выше).

## Как проверить

- **Стенд** `tools/web-test/`. Самопроверка по образцу:

  ```
  func _selftest() -> void:
  	await get_tree().create_timer(0.3).timeout
  	hud.close_dialog()
  	admin_set_day(1)                 # 45 — зима со снегом, 39 — зима без снега
  	enter_location("<локация>", "")
  	me.position = Vector3(<x>, 0, <z>)
  	cam_target = me.position
  	await get_tree().create_timer(1.5).timeout
  ```

  Запуск — `run.mjs` с `min=600` (день), `dist=8`…`12` (ближе), `yaw=` (с какой стороны смотрит камера: `0` — с юга, `1.57` — с востока, `-1.57` — с запада, `3.14` — с севера).
- **Снимки:**
  - минимум с двух-трёх сторон;
  - летом и зимой (день 45);
  - для рынка — днём и вечером (`min=1150`).

  Смотреть: нет ли дыр, светлые ли верхние поверхности на солнце, видно ли то, что внутри, похоже ли на старый рисунок.
- **Нажатия:** самопроверка вызывает `farmnet.act(Vector2i(x, y))` и печатает `hud.dialog_kind` и `hud.toast_label.text` — поведение должно остаться прежним.
- **Основная проверка огорода** (`selftest.example.gd`) — строки `TEST radish picked 2 drops left 0` и `TEST money 100 -> 132`.
- **Перезапуск сервера стенда:** перед новым `serve.py` остановить старый (`pgrep -f "^python3 serve.py"` → `kill`). Иначе новый не займёт порт, и снимок будет со старой самопроверкой.

## Подводные камни

- **Изнанка сверху.** Лицевая сторона — та, с которой вершины идут **по часовой стрелке**. Верх, повёрнутый изнанкой вверх, солнце почти не освещает: он выглядит серым и тусклым (так было с бортиком фонтана и водой). Проверять снимком; для круга вверх — `_disc(..., down = false)`.
- **Под крышей не видно.** Камера смотрит сверху под 50° (урок в [[lessons]]).
- **Масштаб.** Персонаж ростом около 1,9 клетки (спрайт 24 пикселя × растяжение 1,25); стены дома 2,0, конёк 3,3. Мелкие предметы (ящики, табличка) — 0,5–1,2.
- **Сеть:** модель — только картинка, у каждого игрока строится из карты и каталога. Если состояние объекта меняется (открыт/закрыт, сломан), оно должно приходить по сети (через `net_*`) или считаться одинаково у всех (как часы рынка). См. [[network]].
- **Редактор карт** по-прежнему показывает объект старым спрайтом из `"sprite"` — это нормально.
- **Производительность.** Каждая модель — несколько мешей. Сотни одинаковых 3D-объектов (например, камней) на огороде нужно будет объединять (MultiMesh) — проверить на телефоне.
