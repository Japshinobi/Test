# Решения: карты, каталог, изменения карт, сохранение, атлас

## Карта локации: `godot/maps/<id>.json`

Читает `location.gd` (`_init`), пишет редактор карт `editor/map-editor.html`. Поля:

```
{
	"name": "Огород",            // название, его показывают при входе (map.title)
	"id": "farm",                // совпадает с именем файла
	"width": 72, "height": 44,
	"bounds": [6, 6, 45, 35],    // необязательно: проходимый прямоугольник [x0, y0, x1, y1]
	"ground": ["....==...", ...],// строки земли, по символу на клетку; короткие строки дополняются "."
	"objects": [{"id": "tree0", "x": 3, "y": 5}, {"id": "exit", "x": 24, "y": 0, "to": "cross"}, ...]
}
```

- **Объект** — `{id, x, y}` плюс свойства из `props` каталога: `text` (табличка, указатель, пугало, стог, шлагбаум), `to` (выход), `trader` (прилавок).
- **`x, y` объекта** — левый верхний угол. Большой объект (`size`) занимает клетки вправо и вниз.
- **`bounds`** есть только у `cross.json`. За пределами прямоугольника ходить можно только по тропинке `=` (`walkable`). Деревья на краю карты и на краю `bounds` не рубятся (`is_edge`).
- **Редактор `bounds` не показывает и не редактирует**, только сохраняет как было. Менять их — вручную в JSON.
- **Карты загружаются один раз** и лежат в кэше `Location._cache` (`Location.get_loc(id)`). Кэш сбрасывается при загрузке сохранения, подключении и «Начать заново».

Сейчас 5 карт: `farm` (72×44), `cross` (52×42), `market` (40×30), `river` (30×18), `forest` (30×20).

## Каталог: `godot/data/objects.json`

Его читают и игра (`Location.catalog()`, `Location.def(id)`), и редактор. Новый объект, добавленный сюда, сразу появляется в палитре редактора.

### Земля (`ground`)

Поля:
- `key` — символ в карте;
- `id`, `name`;
- `walk` — проходимость;
- `color` — цвет в редакторе;
- `tile` — есть у полей, но игра его не читает.

Символы:

| Символ | Что это | Проходимо |
|---|---|---|
| `.` | трава | да |
| `,` | трава с цветами | да |
| `=` | тропинка | да |
| `~` | вода | нет |
| `P` | место под постройку | да |
| `#` | непроходимо | нет |
| `Q`, `N` | соседские поля (пшеница, подсолнухи) | да |
| `q`, `n` | поля за краем | нет |
| `V` | канава | нет |
| `O` | брусчатка | да |
| `b`, `d` | мост (левый и правый край) | да |

**Картинка земли** выбирается не по каталогу, а кодом: `world.gd` → `_tile_name` и отдельно в редакторе (`groundSprite` в `map-editor.html`). Новый символ земли требует правки в обоих местах и рисунков в атласе (см. [[location]]).

### Объекты (`objects`)

| Поле | Значение |
|---|---|
| `id`, `name`, `group` | имя, название, группа в палитре редактора |
| `sprite` | имя спрайта в атласе (без суффиксов) |
| `seasonal: true` | спрайт меняется по дням: `<sprite>_<вид дня>` (деревья, кусты, дуб) |
| `snow: true` | зимой со снегом берётся `<sprite>_snow` |
| `size: [w, h]` | сколько клеток занимает (по умолчанию 1×1) |
| `block: false` | проходимый (по умолчанию объекты непроходимы) |
| `shadow: false` | без тени |
| `seasons: [...]` | виден и мешает только в эти сезоны (стог — осенью) |
| `props: [...]` | какие свойства задаются в редакторе: `text`, `to`, `trader` |
| `shop: true`, `traders: [...]` | прилавок; спрайт `<sprite>_<торговец или empty>_<0/1 открыт>`; список допустимых торговцев для редактора |
| `model: "house"`, `door: [dx, dy]` | дом строится 3D-моделью; клетка двери — сон |
| `model: "bin"`, `"mailbox"`, `"sign"`, `"signpost"`, `"barrier"` | мелкие постройки в 3D (`world.gd` → `_prop`); шлагбаум ложится вдоль длинной стороны `size` |
| `model: "fountain"` / `"well"` | фонтан или колодец строится 3D-моделью (`_fountain`, `_well`); спрайт — для редактора |
| `model: "stall"` / `"tent"`, `facing` | прилавок или шатёр строится 3D-моделью (`world.gd` → `_shop`), перед смотрит на `south`, `north`, `east` или `west`; спрайт из `sprite` нужен только редактору |
| `color` | у служебных объектов без спрайта (`exit`, `spawn`) — цвет в редакторе |

**Что делает объект при тапе,** решает код (`farm_net.gd` → `act`), а не каталог. Новый объект с поведением требует ветки в `act`.

## Изменения карт (mods)

Файлы карт игра **никогда не меняет**. Что игроки срубили, разбили или скосили, хранится отдельно:

- формат: `farm.mods[<локация>]["x,y"] = изменение`;
- изменение: `{"remove": true}` (убрать объект), `{"replace": "stump"}` (заменить объект), `{"ground": "."}` (сменить землю);
- `Location.apply_mod(x, y, change)` хранит итог: новый `remove` отменяет старый `replace` и наоборот;
- рассылка — `net_mod`;
- при загрузке mods накладываются на свежие карты: `apply_mods`.

**Важно:** изменение привязано к координатам клетки, а не к конкретному объекту. Если после появления сохранений передвинуть объекты на карте в редакторе, старое изменение применится к тому, что теперь стоит в этой клетке (см. [[lessons]]).

## Сохранение

- **`user://save.json`** — пишет `farm_net.gd` → `save_game()`: каждые 20 секунд, утром, при сворачивании и закрытии. Только у хозяина или в одиночной игре. Содержимое:
  - `farm.to_dict()`: `day`, `money`, `shipped`, `mods`, `snow_trod`, `plots`, `drops`, `next_drop`, `snow`;
  - `version: 1`;
  - `minutes`;
  - `invs` и `water` — инвентари и вода по постоянным номерам игроков;
  - `loc` и `pos` — где стоит хозяин.
- **`user://player.cfg`** — постоянный номер игрока (`uid`).
- **Загрузка** — `load_game()`. JSON возвращает числа дробными, поэтому количества приводятся к `int` (`_fix_inv` и т. п.).
- **Новое поле:** добавьте его в `to_dict()` и `from_dict()`, читайте через `d.get("поле", значение_по_умолчанию)`. Иначе старые сохранения сломаются.
- **Ключи** в `shipped` и `plots` — строки (`"radish"`, `"20,12"`). Ключи `drops` при загрузке переводятся в `int`.
- **Удалить сохранение** — `delete_save()` (кнопка «Начать заново»).

## Палитры: `godot/data/palette.json`

Две палитры, «3d» и «2d»: ряды цветов по материалам, от светлого к тёмному. Их читают сборщик атласа (`tools/export-atlas.mjs`) и игра (`godot/scripts/palette.gd`: `col`, `snap`, `quantize`). Подробно — [[pixel-art]].

## Атлас рисунков

- **Файлы:** `godot/assets/atlas.png` (2048×512) и `atlas.json` (`sprites: [{n, x, y, w, h, ax, ay, fy}]`, `shadowBoxes`). `shadowBoxes` в Godot не используются.
- **Источник:** рисунки кодом в `game/sprites.js`. Атлас собирает `node tools/export-atlas.mjs`. Список спрайтов и их имена задаёт `export-atlas.mjs`: новый рисунок нужно добавить и в `sprites.js`, и в список в `export-atlas.mjs`.
- **Если спрайта нет в атласе,** `world.gd` → `_obj` пишет предупреждение «Нет спрайта …» и объект не рисуется, но клетки по-прежнему занимает.
