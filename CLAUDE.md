# CLAUDE.md — «Дедушкин огород»

Читать в начале каждой сессии. Подробности — в базе знаний `knowledge/` (оглавление: `knowledge/README.md`). Общий обзор проекта — `HANDOFF.md`.

## Что за игра

Пиксельная игра-ферма для Android на **Godot 4** (папка `godot/`), в стиле Ragnarok Online.
- Мир объёмный (земля, вода, дом), а персонажи, растения и предметы — пиксельные спрайты, повёрнутые к камере.
- Сюжет: Ваня получил от дедушки Матвея старый дом и заросший огород, растит урожай и продаёт его на рынке.
- Пять локаций, 10 культур, 4 сезона по 12 дней, рынок с торговцами, инструменты.
- Игра вдвоём по Wi-Fi: огород и деньги общие, инвентарь у каждого свой.
- Проект некоммерческий. Цель — попробовать, а при удаче дорасти до уровня Stardew Valley / Sun Haven.

## Правила работы с владельцем

- **Отвечать по-русски, простыми словами.** Владелец не программист и ведёт разработку через ИИ.
- **Просьбы владельца выполнять сразу. Свои идеи — сначала обсудить** и делать только после согласия. Даже маленькое «заодно поправлю».
- **APK собирать только по команде владельца** (когда он скажет, что будет тестировать). Не после каждого изменения.
- **Напоминать об оставшихся проверках вдвоём** перед изменениями в игре и перед сборкой APK. Основной тест на двух телефонах проведён 22.10.2026; что ещё не проверено (деньги и урожай, локации, торговля, вещи гостя, вид Нины) — единственный список в `HANDOFF.md`, раздел 2, «Игра вдвоём». Проверенное оттуда вычёркивать.
- **Ничего не придумывать за владельца** в системах, которых ещё нет (НПЦ, диалоги, события, еда, одежда): сначала вопросы из рецептов.
- Коммитить в рабочую ветку, PR — только по просьбе.
- **Статусы в таблицах `design/*.xlsx`** (подробно — `knowledge/decisions/data.md`):
  - делать в игре можно только строки со статусом **«решено»**; «в игре» — уже сделано;
  - «обсуждаем», «пример», «предложение», «план» — **не делать** без прямой команды владельца. «Предложение» — идея Claude из чата, а не решение владельца, даже если выглядит готовой;
  - заливка: жёлтая — правки владельца, зелёная — внесено Claude в чате, светло-оранжевая (`F8CBAD`) — образцы («пример»). Заливка сама ничего не решает, решает статус;
  - лист «Список культур» в `design/weather.xlsx` не трогать и не переносить: владелец переделывает культуры отдельно.

## Главные технические решения

Подробно: `knowledge/decisions/architecture.md`, `network.md`, `data.md`.

- **Код:**
  - GDScript, без `class_name`: скрипты подключаются через `const X := preload("res://scripts/x.gd")`;
  - сцена и интерфейс строятся кодом (`main.tscn` — один узел со скриптом `main.gd`);
  - тексты для игрока — по-русски прямо в коде.
- **Рендер GL Compatibility** (для слабых телефонов). 1 клетка = 1 единица 3D, X — восток, Z — юг. Спрайты: `Sprite3D` с материалом «стоит на экране ровно» (`atlas.gd` → `upright`), `pixel_size = 1/16` (герои — 1/32), растяжение по высоте `STRETCH = 1.25` (герои — 1.5), без освещения, подкрашиваются по времени суток (`TINT`).
- **Игра вдвоём — «хозяин решает»:**
  - любое изменение мира — только через `farmnet.request(action, args)` → у хозяина `_host(...)` → рассылка `_all` / `_to` методами `net_*`;
  - так работает и в одиночной игре;
  - интерфейс сам ничего не меняет.
- **Общее и личное:** общее — деньги, грядки, ящик, предметы на земле, изменения карт, день. Личное — инвентарь, вода в лейке, локация. Решение владельца: **весь мир синхронизирован у обоих** — и будущие НПЦ, погода, события тоже; личные — дружба с НПЦ, итоги разговоров, свои копии писем.
- **Карты** — `godot/maps/<id>.json`, их правит редактор `editor/map-editor.html`. Каталог земли и объектов — `godot/data/objects.json` (читают игра и редактор).
- **Изменения карт** (срубили, скосили) хранятся отдельно как **mods** по клеткам, файлы карт игра не меняет.
- **Сохранение** `user://save.json` пишет только хозяин; инвентари гостей — по постоянному номеру из `user://player.cfg`. Новое поле сохранения — всегда через `.get(поле, умолчание)`.
- **Рисунки** пока рисуются кодом в `game/sprites.js` → атлас `godot/assets/atlas.png` собирает `node tools/export-atlas.mjs`. Новый спрайт = рисунок в `sprites.js` + имя в `export-atlas.mjs` + пересборка.
- **Предмет** — строка `"вид:ключ"` (`tool:hoe`, `seed:radish`, `prod:radish`, `res:wood`). Описаны в `godot/scripts/farm.gd` (`TOOLS`, `CROPS`, `RES`, `TRADERS`).

## Телефон

Что уже задано в проекте (остальное не решено — спрашивать владельца):
- **Телефоны для проверки:** Xiaomi 12T Pro (владелец, скорость проверять на нём) и Honor Magic 6 Pro (второй игрок).
- **Ориентация** — только горизонтальная: `godot/project.godot` → `window/handheld/orientation=0`, `android/app/src/main/AndroidManifest.xml` → `sensorLandscape` (переворот на 180° разрешён).
- **Разрешение** — базовое 1280×720 (`window/size/viewport_width/height`), масштаб `stretch/mode="canvas_items"`, `aspect="expand"`: интерфейс увеличивается под экран, на вытянутом экране мир виден шире. На Android игра во весь экран (`main.gd` → `_ready`, `WINDOW_MODE_FULLSCREEN`): системные кнопки прячутся, интерфейс на телефоне владельца помещается (22.10.2026). Вырез камеры (safe area) отдельно не учитывается.
- **Кнопки** (`godot/scripts/hud.gd`): ячейка панели `SLOT := 58` (в пикселях базового экрана 1280×720), стрелки рядов — `SLOT / 2`; шрифт по умолчанию 18 (`_theme`); долгое нажатие на ячейку — 0,55 с (владельцу удобно). Размер кнопок владельцу пока хватает, мелкий текст читается (22.10.2026). Интерфейс позже перерисуем в PixelLab.
- **Камера** (`main.gd`): приближение двумя пальцами, расстояние `ZOOM_MIN := 8.0`…`ZOOM_MAX := 30.0`.
- **Android:** `minSdk 24`, `targetSdk 35` (`android/app/build.gradle`); рендер GL Compatibility. Владелец решил (20.10.2026): ориентир — флагманы 2022–2024 годов.

## Файлы игры (`godot/scripts/`)

- `main.gd` — ввод, камера, ходьба, время, свет, переходы, сеть.
- `farm.gd` — правила и предметы.
- `farm_net.gd` — действия игроков, рассылка, сохранение.
- `world.gd` — 3D-картинка локации.
- `location.gd` — карта и mods.
- `weather.gd` — погода: шансы по сезонам, план дня, как выглядит (состояние — `farm.gd` → `weather`).
- `hud.gd` — интерфейс.
- `avatar.gd` — персонаж; `atlas.gd` — атлас; `palette.gd` — палитры 3D и 2D (`data/palette.json`); `sfx.gd` — звуки.

## Как проверять изменения

Подробно: `tools/web-test/README.md` и раздел «Как проверить» в каждом рецепте.

1. **Тестовый стенд** (игра в браузере без Godot):

   ```
   sh tools/web-test/setup.sh                      # один раз: скачать движок
   cd tools/web-test && python3 serve.py ../../godot [свой_тест.gd] &
   node run.mjs "http://127.0.0.1:8765/index.html?farmtest=1" 25000 shot.png
   ```

   - Самопроверка — функция `_selftest()` (образец `selftest.example.gd`), печатает строки `TEST ...`.
   - Снимок `shot.png` смотреть глазами.
   - Ошибки разбора скриптов видны в выводе.
   - **Сеть на стенде не работает.**
2. **Игра вдвоём** — только в Godot на компьютере (2 экземпляра) или на двух телефонах у владельца.
3. **Карты** — открыть в редакторе, пересохранить, `git diff` должен показывать только нужное.
4. После правок проверять: нет ли в выводе «Нет спрайта», ошибок GDScript, строк `SCRIPT ERROR`.

## Ведение базы знаний

- **В конце задачи, если появилось что-то новое или нашлась ошибка,** коротко предложить владельцу:
  - какой рецепт дополнить или исправить;
  - какой урок записать в `knowledge/lessons.md`.

  После мелких правок без новых знаний ничего не предлагать. Записывать **только после согласия владельца**.
- **Если рецепт разошёлся с кодом** — верить коду, сказать об этом владельцу и предложить исправление рецепта.
- **Новый вид задач** — новый рецепт по шаблону `knowledge/_template-recipe.md` и строка в таблице выше и в `knowledge/README.md`.
- **Правила записи:**
  - имена файлов в `knowledge/` — латиницей, текст — по-русски;
  - связи — ссылками `[[имя-файла]]`;
  - каждое имя функции и путь проверять поиском по коду.
